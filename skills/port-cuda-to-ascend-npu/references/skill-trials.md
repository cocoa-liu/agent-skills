# 如何试跑和改进本 skill

仅在维护 skill、用户要求试跑或评估其泛化时读取；不是每次模型迁移的附加流程。

初版是可执行说明和证据约定，不代表已经通过真实模型迁移验证。格式校验、人工走查和真实 GPU/NPU 试跑分别记录，不能相互替代。

## 最小试跑方式

固定同一套 skill，提供一次足够明确的任务输入，然后让代理自主运行到验收交付或有依据的暂停。输入包含仓库/版本、模型、可用目标环境和验收要求；已在项目配置中的信息不重复输入。不要求用户在每一步追加 prompt，也不把零提问当作成功标准。

使用隔离 checkout 和可用资源，记录实际执行路径。历史 PR 合并后的代码适合验证“已有支持无需多改”；检验能否发现旧问题需要选择当时的迁移前状态，并检查共享依赖是否齐备。

已有授权不等于可占用他人设备或删除其他进程。试跑配置只使用任务允许的资源，不把 SSH、驱动重装、云实例等操作固化进 skill。

## 先做三个有区分度的场景

| 场景 | 观察什么 |
|---|---|
| 已有能力足够，只需配置或零改动 | 能否运行并验收，而不强造代码修改；无代码改动也报告测试证据 |
| 已知历史模型，如 Voxtral 或 FishAudio 的迁移前状态 | 是否找到共享实现；每项修改有原因；真实请求、精度和 benchmark 是否落实 |
| 未写入案例的模型 | 是否能发现不同的能力缺口；必要时合理扩展；是否依靠项目事实而非复刻旧补丁 |

没有 NPU 时可做局部行为检查和流程演练，但“真实硬件迁移有效性”保持待验证。历史案例已包含修复线索，因此三个 PR 的回放是利用案例完成交付的执行检验，不是盲测。先从 Voxtral 迁移前状态跑完整闭环，再扩展到 FishAudio 和 Qwen3-Omni；不要求复刻原补丁或遵守固定步骤顺序。泛化检验另选案例未覆盖的模型，只提供原始任务、环境和文件，不泄露预期修复。

## 记录结果

每轮保存 skill 版本/内容标识、任务与源码版本、资源和基线来源、完整迁移报告。维护者另外简记：

| 项目 | 判定 |
|---|---|
| 所需功能、精度与基础 benchmark | 各自通过 / 失败 / 待验证 |
| 复用和改动 | 必需修改、无关修改或重复实现及具体位置 |
| 用户干预 | 提问/补充原因；区分真实资源缺口与可自行发现的信息 |
| 返工与耗时 | 首次有效请求、最终验收耗时、额外尝试及原因 |
| 新问题 | 原始失败证据；属于 skill、环境、代码还是评测条件 |

有无 skill 的对照应保持初始 checkout、模型配置、工具与资源尽量一致。历史案例是回归检查，未见模型更能检查泛化；不要仅用最终 diff 大小衡量质量。

发现一次失败，优先修正最小的遗漏或歧义。模型特有条件记入案例；有跨案例证据后再考虑提升为通用指令。不因单次失败添加所有任务都必须走的新步骤。完成这些试跑后，再决定是否需要自动采集、比较或调度脚本。


## 验收循环的行为检查

维护此版本时，用已有结果或隔离的小用例检查以下决策，不要求再跑全部模型：

- 全部必需项通过：交付并停止扩展。
- 同协议指标越线：找到失败样本、设计区分原因的对照并继续修复；不能以报告结束。
- 均值改善但出现串请求/严重异常：仍进入问题处理。
- 基线协议不同、没有精度阈值或只跑了7/1088条：不得报完整精度通过。
- 修复评分：按主文取得同一评分方法下的双方结果；修改推理/调度后必须对应新补丁复验。
- 复测时好时坏：保留全部轮次，不能选最好的一轮过关。
- 最终共享依赖改变后只有少量请求通过：继续最终组合完整精度与基础 benchmark，不得引用旧全量完成交付。
- 新模型没有历史 NPU 补丁：从标准答案、原始实现和局部语义建立评价依据；没有可比基线不声称无退化。
- 实验不再提供定位证据：先回顾和调整对照；仍无可执行的有效下一步时保存现场请求针对性协助，不宣称修好或无限重跑。
- 外部设备被占用：使用其他已授权可用资源，或记录具体阻塞；不能停止他人任务。
- 为跑通而关闭所需图执行或将模型计算移到 CPU：即使输出正确也不能交付；恢复所需 NPU 执行路径并验证，无法支持则汇报。NPU 性能落后只触发分析和讨论，不授予框架或公共算子修改权限。
- 原始要求包含流式功能，但只验证了离线推理：审查应发现遗漏；额外改进建议不能临时变成交付门槛。
- 模型侧仍未达标：有合理下一步则继续定位；证据指向框架限制或合理尝试不再提供新信息时，汇报方案并讨论，不能无限试错，也不能自行改框架。把共享函数替换代码放进模型目录不能免除审批。
- 只有 NPU 和公开 GPU 成绩：核对比较条件并填写对比表；GPU 未公开逐样本明细不自动判失败，关键条件不明则不能判通过。换评分方法后必须有同一方法下的 GPU 结果；历史成绩不充当当前补丁的 CUDA 回归证据。
- 已有测试能发现关键功能失败：核查并复用证据，无需机械新增故障注入；任何必需项或独立审查未通过，都不可交付。

这些是验收行为检查，不是证明Skill已能自主处理陌生模型。真实模型试跑另记版本、通过项和未解决项。

独立陌生模型试跑不提供该目标的现成迁移补丁或预期根因，但允许查项目公共能力和原始参考实现。重点观察能否自主发现并修复故障、重新完整验收，以及无法解决时能否有依据地暂停；不只记录是否产出补丁。
