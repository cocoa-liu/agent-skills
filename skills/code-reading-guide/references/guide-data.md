# Guide data contract

`guide.json` 是作者编写的讲解数据；源码由构建器从仓库快照读取，不手抄进 JSON。所有文字字段都是纯文本，支持换行，不解释 Markdown/HTML。

下面是可以使用的最小结构；行号是示例，使用前换成实际阅读过的位置。不要把示例的行为当作待讲解仓库的事实。

```json
{
  "title": "订单金额计算：从输入到最终金额",
  "subtitle": "先认识职责，再沿一笔订单读代码",

  "audience": "会写 Python，尚不熟悉这个项目",
  "url": "https://example.org/repository/pull/123",
```

## Required fields and semantics

- 顶层 `title`、`overview`、`blocks`、`trace`、`maintenance`、`evidence` 必须存在。`subtitle`、`language`（默认 zh-CN）、`audience`、`url`、`limitations` 可选。不要为了填表编造问题或数据；可诚实写未测/推导。
- `overview`：`summary`、`problem`、`scenario`、非空 `flow`。整库阅读没有前后对比时省略 `scenario.before`，`after` 表示正常执行结果。`flow_note` 用于区分数据流和实际调用方向。
- `blocks`：按建议阅读顺序排列。`id` 用稳定的英文小写/数字/短横线，例如 `request-entry`；所有 block 引用都必须存在。阶段名称是内容，不固定为模型或 Web 服务的生命周期。
- 每个 block 的所有示例字段以及非空 `explanation`、非空 `refs`、`checkpoint` 都必须存在。可以有多个短的源码片段，先后顺序就是推荐阅读顺序。
- 每个 ref 都需示例中的字段；只有 `version`（默认 head）和 `caution` 可省略。`steps` 至少一项，行号包含两端，且必须落在 ref 范围内。按逻辑解释，不为了凑数把一行代码拆成三段。注释/空行可与相邻逻辑一起讲；片段不能大到掩盖未讲解的关键分支。
- `version="head"` 指 `--revision` 的 commit，或显式 `--working-tree` 捕获的工作区；`version="base"` 指 `--base`。删除的文件、旧默认值、以前的调用逻辑可指向 base。二者行号分别核对，不能混用。
- 路径必须是仓库内、相对于仓库根的普通文本文件。生成器拒绝 `..`、绝对路径和符号链接，不跟随外部文件。跨仓库依赖作为另一个独立导读或用已核对的说明交代，不伪装成本仓库文件。
- `checkpoint.answer` 是 choices 的零基索引；至少两个选项。`explanation` 解释答案，`simpler` 帮助读者回到最小例子，`deeper` 提供进一步维护思考。不要只写“对/错”。
- `trace` 应覆盖选定输入的起点到终点，具体值可以是推导或假设，但须标注依据；中间结果没观测到就写“未知/未记录”，不要补造 token、日志或测量数值。
- `basis` / `kind` 仅使用 `observed`（实测/已直接核对）、`derived`（推导）、`historical`（历史结果）、`hypothesis`（推测）。源码能直接核对的事实可用 observed，并在 detail 中说明是静态阅读，而不是运行测试。
- `evidence[].detail` 写出处、版本、实验条件或无法确认的部分。工具不验证自然语言结论；作者需要验证。`limitations` 汇总会影响结论的实际边界，不添加通用警告。

## Snapshot and update behavior

构建器解析 revision/base 为完整 commit，读取源码一次，生成 SHA256 清单和内容指纹，并将需要的源文件嵌入页面。源码弹窗展示该快照的完整文本，文件/行号链接无需访问仓库网站。HTML 文件可离线独立使用；同目录还生成 `<output>.manifest.json`，用于核对文件摘要和构建版本。

工作区模式显式标为 working-tree，不声称能用 Git commit 完整还原；清单包含每个嵌入文件的摘要。生成器拒绝覆盖仓库已跟踪文件，并拒绝把输出写回输入 spec。需要替换仓库里已有文档时，先生成临时产物、核对 diff，再按用户授权复制。

源代码改动后，从被引用的快照重新核对讲解与行号，再构建。工具能拦截越界行号，但不能识别“行号仍合法、文字却解释了另一个函数”的错误。尤其检查默认参数、调用生命周期、测试结论和 UI 中显示的章节数量是否仍正确。

## Meaningful quality checks

- 所有可见代码片段有实际源码和自己的讲解；没有“看链接自行理解”的空块。
- 调用者与数据输入输出可连成闭环；注册不是执行，声明不是已验证支持。
- 同一例子贯穿，不随意切换数据来掩盖中间边界；物理 padding/容量与有效内容分开。
- 每次只读一个关键块；用户可以主动跳读，答题不自动跳转，也不把跳过标成理解。
- 存储被浏览器禁用时页面仍可读、可导出，且提示进度未持久化。源文件里出现 HTML/script 字符时只能显示为文本。
- 桌面和窄屏都能看源码；长代码在代码区横向滚动，而不是把整页撑宽。
- 文档验证与业务测试分开汇报；从未运行的工作不能被模板里的“已验证”文字误报为完成。


## PR diff reading progress

提供 `--base` 时，构建器自动生成 `review`，作者不需要在 guide.json 重复写 diff。base 应取 PR 的 merge-base，head 固定到正在阅读的提交。文件清单来自 Git raw diff（包括重命名），文本片段从两端的原始 blob 按行比较生成，默认带三行上下文；其分段对齐可能与 Git 的默认 diff 算法不同，但不省略改动内容。

- **范围**：所有变更文件，而不只是 refs 中挑出来讲解的文件。新增行和删除行分别使用新/旧行号，可分别标记；上下文只是辅助阅读，不计入变更进度。二进制、非 UTF-8、子模块、空文件、纯重命名/文件模式变化显示文件级变更项，也可以标记和批注。
- **阅读布局**：类似 GitHub 的三栏布局。左侧为可折叠目录树，可按文件名筛选；中间为保留缩进、行号和增删标记的代码视图，长行默认横向滚动，也可开启换行；右侧为独立批注栏。阅读页取消正文最大宽度限制，将章节侧栏收成顶部导航，文件树和批注栏均可收起以扩大代码区。
- **文件阅读位置**：每个文件单独保存可见代码行、行内偏移、横向滚动位置和当前批注行。切换回来时，在代码换行和批注高度计算完后恢复，批注栏同步跟随；重复点击当前文件不重置，第一次打开的文件从开头显示。优先按代码行恢复，避免长批注或换行引起的高度变化使阅读位置偏移。滚动时更新内存位置、短暂防抖后写入浏览器，离开页面时补存，刷新后仍可继续阅读。
- **批量选择**：灰色未读、绿色已理解、黄色疑问/暂缓。直接拖选代码文字即可选择所经过的改动行，随后统一标色；Ctrl / Cmd 拖选可以追加，文本仍可正常复制。也可输入新行号或旧行号的起止范围，选择替换当前选择或追加；空范围保留已有选择。保留单行勾选、Shift 连选和整段/整文件选择，显示已选行数，上下文不计入阅读进度。
- **完整批注**：右侧默认按代码行号展开当前文件的全部已有批注。每条只保留可编辑内容，去掉标题、状态下拉框、边框和内边距；空批注和短批注默认一行（22px），内容软换行或输入换行时自动增高，删短后自动缩回，不截断为摘要。阅读状态在代码区选择行后统一标色。点击代码行或批注气泡添加新批注；输入时不重建编辑框，避免光标或输入内容丢失。手机上批注栏排列在代码区下方。批注不是在源代码中插入注释。
- **行对齐与跟随**：桌面端批注第一行文字与对应代码行水平对齐。只按内容高度为相邻长批注保留足够行高，短批注不添加额外空白；滚动代码区或批注区时，另一侧保持同样的垂直偏移。有批注的代码行常态保留蓝框，清空批注后取消常态蓝框；用更深的蓝框、连接箭头、行首指示和联动高亮标出悬停或正在编辑的行，顶部行号提示区分新/旧行号。处理程序引发的滚动回声，避免反向同步覆盖新的滚动操作；编辑、换行、缩放、收起侧栏之后须重新计算位置。仅修改展示高度，不修改源代码或持久化行标识。窄屏或收起批注时取消额外行高；打开长批注时保持代码文字所在行可见，而不是批注底部。
- **语法高亮**：内联 vendored Highlight.js 11.11.1 常用语言包，源码文本经过高亮后仍须逐行完全一致。未知语言保留等宽代码视图；不依赖 CDN。许可证随 `assets/highlight.LICENSE` 分发，并保留在 JS 注释中，因此生成的独立 HTML 也携带许可证。
- **自动保存**：绑定独立的 PR 代码快照 ID，使用浏览器本地存储；刷新、关闭页面及正常重启同一浏览器后恢复。教学标题、解释和章节调整不改变该 ID。代码版本改变则使用另一份进度，保留旧版本记录而不自动错贴到新行。
- **备份与迁移**：JSON 导出/导入包含逐行状态、批注和各文件阅读位置，导入前校验整个备份的 schema、代码快照、行 ID、文件位置和字段类型。不兼容时不写入任何记录；兼容时合并备份中的行和位置，保留其他记录。明确恢复灰色/清空批注也要保存，避免旧 HTML 备份再次把它们恢复出来。
- **带标记 HTML**：下载一个内嵌当前阅读记录的新 HTML 文件；其在没有原浏览器缓存的环境中也能恢复。它不会自动覆盖正在打开的原始 HTML。存在更新的浏览器记录时，按逐行更新时间合并，避免老备份覆盖后续工作。
- **可见状态**：显示已恢复/已自动保存/保存失败。浏览器禁用存储、清理数据或无痕会话结束时，不能保证本地存储保留，因此仍提供可携带的备份；不要声称存在服务端同步。
- **工作区模式**：`--working-tree --base ...` 比较已跟踪的工作区内容，不纳入未跟踪文件；快照包含实际内容摘要。单独生成无 base 的模块导读时，不出现虚构的 PR 进度页。

`review_diff.py` 负责完整改动数据与稳定行标识；`review.css` / `review.js` 是独立组件，构建器将它们与 `highlight.min.js` 一起内联，最终仍是无需网络的 HTML。旧版导读也可嵌入该组件并调用 `CodeReadingReview.mount(container, reviewData)`，在路由中按阅读进度视图切换 body 的 `review-page` 类即可启用宽屏布局，不必重写原有教学章节。布局升级保持原有 `code-reading-review:v1:` 存储键与备份 schema。可选的 `active_row` 记录当前批注位置；`file_positions` 按文件 ID 保存行索引、偏移和更新时间，按时间合并不同窗口的记录；缺省时仍可恢复旧颜色和批注。

`check_review.cjs` 可单独验证一个已嵌入组件的 HTML；默认完整浏览器检查也会调用它。测试使用隔离浏览器配置和临时副本，不把测试颜色/批注写进交付的原始页面。

其中 `check_alignment.cjs` 检查代码与批注首行文字的位置误差、短批注一行高度、内容增减时自动扩缩、相邻批注不重叠、两侧实际滚轮同步、悬停/焦点指示、超长批注编辑、换行与窗口缩放、窄屏恢复、收起侧栏及旧进度兼容；仅靠截图或“scrollTop 相同”不能证明行对齐。

`check_positions.cjs` 在至少两个较长源码文件之间验证位置独立恢复、横向滚动、刷新、换行后的行定位、批注跟随，以及 JSON 和带标记 HTML 恢复；没有足够文件时明确跳过。
